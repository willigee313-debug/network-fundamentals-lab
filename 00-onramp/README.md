# 00장. 온램프 — 읽기 전에 (준비물)

> 이 시리즈의 유일한 "고장 없는" 장. 01장이 곧장 `ip addr add 10.10.10.1/24`로 시작해도
> 벽이 되지 않도록, **딱 세 가지**만 챙긴다: ① IP/서브넷 표기 읽는 법 ② L2/L3 계층 감각
> ③ 도구 3종(`ip`/`ping`/`tcpdump`) 손 익히기. 이미 아는 사람은 건너뛰고 01장으로.

---

## 1. IP 주소와 서브넷 마스크 — `/24`가 뭔가요

### 1-1. IP 주소 = 32비트
`10.10.10.1`은 사람용 표기일 뿐, 실체는 32비트다:
```
10      .10      .10      .1
00001010 00001010 00001010 00000001
```

### 1-2. `/24` = "앞 24비트가 네트워크"
`10.10.10.1/24`에서 `/24`(서브넷 마스크)는 **앞 24비트 = 네트워크 부분, 나머지 8비트 = 호스트 부분**이라는 선언이다.
```
10.10.10.1/24
└ 네트워크: 10.10.10.0  (앞 24비트)
└ 호스트 범위: 10.10.10.1 ~ 10.10.10.254  (뒤 8비트 = 2^8-2 = 254개)
```
**두 IP가 "같은 네트워크"인가 = 마스크만큼의 앞 비트가 같은가.** 이 판단이 이 시리즈 전체의
출발점이다 (같은 네트워크 → 직접 통신 / 다르면 → 라우터 필요, 01·04장).

### 1-3. 연습 (답은 아래 접기)
1. `10.10.10.1/24` 와 `10.10.10.200/24` — 같은 네트워크인가?
2. `10.10.10.1/24` 와 `10.10.20.2/24` — 같은 네트워크인가?
3. `192.168.1.100/16` 과 `192.168.99.1/16` — 같은 네트워크인가?
4. `10.5.2.10/24` 네트워크의 주소 개수는? `/30`이라면?

<details><summary>답 보기</summary>

1. **같다** — 앞 24비트(10.10.10)가 동일.
2. **다르다** — 세 번째 옥텟(10 vs 20)이 다름 = 24비트 안에서 불일치. → 01장 실습 B가 이 상황이다.
3. **같다** — /16은 앞 16비트(192.168)만 본다. 마스크가 판단을 바꾼다!
4. /24 = 호스트 8비트 = 254개(전체 256 − 네트워크·브로드캐스트 2). /30 = 호스트 2비트 = **2개** (라우터 간 전송망에 애용, 04장부터 등장).
</details>

## 2. L2와 L3 — 두 개의 주소, 두 개의 세계

```
┌───────────────────────────────────────────────┐
│  L3 (IP 계층)   : IP 주소 · 라우터 · "네트워크를 넘는" 배달   │
│                   예) 10.10.10.1 → 편지의 "주소"          │
├───────────────────────────────────────────────┤
│  L2 (이더넷 계층): MAC 주소 · 스위치 · "같은 구간 안" 배달    │
│                   예) aa:c1:ab:.. → 옆방까지 전달하는 손    │
└───────────────────────────────────────────────┘
```
- **L2 (MAC)**: NIC에 박힌 고유 주소. **같은 케이블/스위치 구간 안에서만** 유효한 배달 수단.
- **L3 (IP)**: 설정으로 부여하는 논리 주소. **구간을 넘어** 목적지를 찾는 기준.
- 모든 IP 통신은 결국 L2 프레임에 실려 나간다 → "IP는 아는데 MAC을 모르면?"이 01장(ARP)의 주제.
- 시리즈의 진행이 곧 이 계층 사다리다: L2(01–03) → L3(04–06) → 그 위(08+).

## 3. 도구 3종 투어 (연습장에서 15분)

```sh
./clab.sh deploy 00-onramp/playground.clab.yml     # h1 ── h2 직결, 고장 없음
```

**① `ip` — 내 상태 보기** (실측 예시)
```sh
docker exec clab-00-onramp-h1 ip -br addr show eth1
# eth1@...  UP  10.0.0.1/24 ...          ← 인터페이스/상태/주소 한 줄 요약
docker exec clab-00-onramp-h1 ip route
docker exec clab-00-onramp-h1 ip route get 10.0.0.2   # "이 목적지에 어떻게 가나"
```

**② `ping` — 왕복 확인**
```sh
docker exec clab-00-onramp-h1 ping -c1 10.0.0.2
# 1 packets transmitted, 1 received, 0% packet loss     (실측)
```

**③ `tcpdump` — 패킷 눈으로 보기** (터미널 2개)
```sh
# (터미널1) h2에서 엿듣기
docker exec clab-00-onramp-h2 tcpdump -nli eth1 icmp
# (터미널2) h1에서 ping
docker exec clab-00-onramp-h1 ping -c1 10.0.0.2
```
✅ 터미널1에 이렇게 보이면 성공 (실측):
```
10.0.0.1 > 10.0.0.2: ICMP echo request, id 28, seq 1
10.0.0.2 > 10.0.0.1: ICMP echo reply,   id 28, seq 1
```
> 옵션 암기: `-n`(이름 해석 끄기=빠름) `-l`(줄 버퍼) `-i eth1`(인터페이스) `-c N`(N개만 잡고 종료)
> — 이 시리즈 내내 이 조합을 쓴다.

```sh
./clab.sh destroy 00-onramp/playground.clab.yml    # 정리
```
